用简单的方式构建个人博客

在这个框架横行的时代，有时候回归纯 HTML/CSS/JS 反而能带来更清晰的思考。

我一直在思考一个问题：构建一个个人博客，到底需要多复杂的技术栈？

现在的答案似乎是——非常复杂。你需要一个框架（React/Vue/Next.js），一个 CSS 方案（Tailwind/CSS Modules/Styled Components），一个构建工具（Vite/Webpack），一个部署平台（Vercel/Netlify），可能还需要一个 CMS（Notion/Contentful/MDX）。

好的技术选择不是选最流行的，而是选最适合的。

为什么选择纯 HTML/CSS/JS

答案很简单：因为这是一个博客。博客的核心是内容，不是技术。读者来你的博客是为了阅读你的文字，不是为了体验你的前端工程能力。

纯 HTML/CSS/JS 带来的好处：

  • 零构建时间 — 不需要等待 npm install，不需要编译，改了就生效
  • 极致性能 — 没有 JavaScript bundle，没有 hydration，页面秒开
  • 永久可用 — 10 年后这些文件依然可以正常打开
  • 通用技能 — HTML/CSS/JS 是所有 Web 开发的基础，无论用什么框架都需要

CSS 变量实现主题切换

CSS Custom Properties 是实现主题切换最优雅的方式。你只需要在 :root 中定义颜色变量，然后在 [data-theme="dark"] 中覆盖它们：

:root {
  --color-bg: #fafafa;
  --color-text: #1a1a1a;
}

[data-theme="dark"] {
  --color-bg: #0a0a0a;
  --color-text: #e5e5e5;
}

切换主题只需要一行 JavaScript：

document.documentElement.dataset.theme = 'dark';

排版的重要性

对于博客来说，排版就是体验。好的排版应该是「透明的」——读者不会注意到它，但会感受到阅读的愉悦。

几个关键原则：

  1. 行宽控制 — 每行 60-75 个字符，约 720px
  2. 行高 — 正文 1.7-1.85，让文字有呼吸感
  3. 字间距 — 标题适当收紧 -0.02em，正文自然
  4. 留白 — 段落之间、标题与正文之间要有足够的间距

响应式不是缩放

很多人理解的响应式设计就是「在小屏幕上缩小字号」。但真正的响应式设计是重新思考内容在不同设备上的呈现方式。

在移动端，你可能需要：

  • 折叠导航为汉堡菜单
  • 减少页面边距
  • 调整时间线布局为垂直排列
  • 确保触摸目标足够大（至少 44px）

写在最后

选择简单的技术不代表要牺牲用户体验。恰恰相反，简单往往意味着更好的体验——更快的加载、更少的故障、更久的可用。

下一步，我打算给这个博客加上基于 Markdown 的内容管理，让写作体验更加流畅。但即使不升级，现在的版本也已经足够好了。

毕竟，最重要的永远是内容本身。
